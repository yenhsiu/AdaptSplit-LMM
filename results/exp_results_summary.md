## 核心分析

### 發現 1：POPE 和 TextVQA 的最優策略完全相反

| | POPE | TextVQA |
|---|---|---|
| 各 budget 最優均一策略 | All B=1 全贏 | 高 budget → B=2 略勝，低 budget → B=1 |
| MME-opt vs All B=1 | 輸（每個 budget 都輸） | 贏（每個 budget 都贏） |

- **POPE**（物體幻覺，Yes/No 判斷）：純粹靠 token 數量，量化精度幾乎無貢獻
- **TextVQA**（文字辨識）：token 精度有幫助，MME-opt 的混合量化策略在此奏效

### 發現 2：「Token 數量主導」的結論需要細化

原本的結論「多 token + 低 bit > 少 token + 高 bit」只在 POPE 完全成立。TextVQA 的表現顯示 **token 質量（精度）也有獨立貢獻**——在 N 相同時，B=2 和 B=4 的表現互相競爭，不能斷言 B=1 一定最優。

### 發現 3：MME-opt 是跨 task 的好策略，但不是最優

MME-opt 在 TextVQA 上每個 budget 都贏過所有均一量化策略，說明它學到了某種普適的分配原則（少量高精度 + 大量低精度）。但在 POPE 上全部輸給 All B=1，代表它消耗了不必要的精度 bit，而這些 bit 本可以多傳 token。

### 發現 4：「6.25% 超越 baseline」只在 MME 成立

| Benchmark | 589,824 budget 結果 | vs Baseline |
|---|---|---|
| MME | 1873.44 | **+0.6% ↑** |
| POPE F1 | 0.8521 | -0.7% |
| TextVQA | 55.15% | -1.0% |

核心 claim 需要修正：並非「超越 baseline」，而是「在 6.25% 傳輸量下可達到接近 baseline 的精度（差距 < 1%）」。

## 接下來要做的實驗

### Task-Specific 搜索（3 個 budget 點）

對 POPE 和 TextVQA 分別跑 `quantization_search.py`，找各 task 的最優 (n4, n2, n1)。

**選定的 budget 點：**

| Budget | 原因 |
|---|---|
| 115,500（1.22%） | 低頻寬，各策略差異最大 |
| 266,240（2.82%） | 中段，有現有結果可對比 |
| 589,824（6.25%） | 最接近 baseline 的關鍵點 |

> 25,600 / 51,200 不跑：N < 50，搜索空間太小，結果可預測。

**預期產出：**
- POPE-optimal 配置 vs MME-optimal 配置的差異
- TextVQA-optimal 配置 vs MME-optimal 配置的差異
- 量化「為什麼 POPE 不需要精度」的具體數據

**後續方向（視結果而定）：**
- 若各 task 最優配置差異大 → 研究 task-aware 動態分配機制
- 若差異小 → 設計 multi-objective 搜索，找一個 universal 最優配置在三個 benchmark 上都優於均一量化
